# Google OAuth Issue Analysis and Fix Plan

## Problem Summary
User can authenticate with Google, but:
1. User is not added to the database
2. Frontend does not redirect to `/main/dashboard`

## Architecture Overview

### Two OAuth Flows
1. **Passport Flow (redirect-based)**: `GET /auth/google` → Google → `GET /auth/google/callback`
2. **Token Flow (popup-based)**: Frontend uses `@react-oauth/google` → `POST /auth/google/token` (used by frontend)

Frontend uses the **token flow** - see `LoginPage.tsx:30-46`

## Code Flow Analysis

### Frontend (`LoginPage.tsx:30-46`)
```typescript
const login = useGoogleLogin({
  onSuccess: async (tokenResponse) => {
    const response = await googleAuthApi(tokenResponse.id_token);  // sends to /auth/google/token
    localStorage.setItem("access_token", response.access_token);
    localStorage.setItem("refresh_token", response.refresh_token);
    navigate("/main/dashboard", { replace: true });
  },
  onError: (error) => console.error("Google login error:", error),
});
```

### Backend Endpoint (`auth.controller.ts:39-44`)

### Backend Token Verification (`auth.service.ts:168-196`)
```typescript
async verifyGoogleToken(googleToken: string): Promise<ITokenResponse> {
  const { OAuth2Client } = require('google-auth-library');
  const clientId = this.configService.get<string>('GOOGLE_CLIENT_ID');
  const client = new OAuth2Client(clientId);
  const ticket = await client.verifyIdToken({
    idToken: googleToken,
    audience: this.configService.get<string>('GOOGLE_CLIENT_ID'),  // Same client ID
  });
  const payload = ticket.getPayload();
  return this.googleLogin({ googleId: payload['sub'], ... });
}
```

## Potential Issues Identified

### Issue 1: Audience Mismatch in Token Verification
In `auth.service.ts:179-182`, the `verifyIdToken` uses the same `GOOGLE_CLIENT_ID` for both client creation and audience verification. This should work IF the token was issued to this exact client ID.

**However**: The Google OAuth consent screen settings might have a different redirect URI configured than what's in the `.env` file.

### Issue 2: No Error Handling/Debugging in Auth Service
The `auth.service.ts` has no `console.log` statements for debugging. Errors are silently caught without any visibility.

### Issue 3: Potential Token Format Issue
The `@react-oauth/google` library's `useGoogleLogin` hook provides `tokenResponse.id_token`. This is a JWT that should be verifiable by `google-auth-library`.

## Diagnosis: Silent Error Suppression

Based on user feedback (no error shown, returns to login, no tokens), the issue is likely:
- The `catch` block in `GoogleLoginButton` (line 39-41) calls `console.error` but doesn't show error to user
- User may not have browser console open to see the error
- Backend is likely returning an error (401 Unauthorized from `verifyGoogleToken` or 409 Conflict from user creation)

## Fix Plan

### Step 1: Fix Frontend Error Display
Add error state to `GoogleLoginButton` to show errors to user instead of just logging to console.

### Step 2: Add Backend Debug Logging
Add console.log to `auth.service.ts` methods to trace the error.

### Step 3: Verify Google Token Verification
The token verification in `verifyGoogleToken` might be failing - check if `GOOGLE_CLIENT_ID` matches what Google has configured.

### Step 4: Check Database User Creation
If token verification passes, the user creation might be failing.
