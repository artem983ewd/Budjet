# Bug Fix: Category Creation Fails - Token/User ID Issue

## Problem
When creating a category, the API returns `{"errors":{"general":"Что-то пошло не так"}}`.

## Root Cause
The JWT strategy (`jwt.strategy.ts:22`) returns `{ userId: payload.sub, email: payload.email }`, meaning the authenticated user object has `userId` property, NOT `sub`.

However, all controllers use `req.user.sub`:
- `categories.controller.ts` - 5 occurrences
- `transactions.controller.ts` - 6 occurrences

This causes `undefined` to be passed as `userId` to services, resulting in TypeORM errors when trying to save entities with a `null` user relation.

## Fix Required

### 1. Update `backend/src/categories/categories.controller.ts`
Change all `req.user.sub` to `req.user.userId`:
- Line 25: `req.user.sub` → `req.user.userId`
- Line 30: `req.user.sub` → `req.user.userId`
- Line 35: `req.user.sub` → `req.user.userId`
- Line 44: `req.user.sub` → `req.user.userId`
- Line 49: `req.user.sub` → `req.user.userId`

### 2. Update `backend/src/transactions/transactions.controller.ts`
Change all `req.user.sub` to `req.user.userId`:
- Line 28: `req.user.sub` → `req.user.userId`
- Line 33: `req.user.sub` → `req.user.userId`
- Line 38: `req.user.sub` → `req.user.userId`
- Line 48: `req.user.sub` → `req.user.userId`
- Line 56: `req.user.sub` → `req.user.userId`

## Verification
After fix, create a category via the UI - it should succeed.
