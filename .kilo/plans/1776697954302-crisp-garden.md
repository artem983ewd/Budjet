# Frontend Bug Fixes Plan

## Bug 1: Adding category from Income tab creates expense category

**Root Cause:**
In `DashboardLayout.tsx` line 14-16, the `addMainCategory` function always hardcodes `type: "expense"`:
```typescript
const addMainCategory = (name: string, icon: IconName) => {
  createCategory.mutate({ name, type: "expense" as const, icon });
};
```
The `AddCategoryModal` is rendered in `DashboardLayout`, which is a shared wrapper for both Income and Expense tabs. The modal doesn't know which tab is currently active.

**Fix:**
1. Modify `AddCategoryModal` to accept a `type` prop
2. Update `DashboardLayout` to determine the current tab type (income/expense) based on `location.pathname`
3. Pass the correct type to `AddCategoryModal`

## Bug 2: Adding subcategory creates a new category instead

**Root Cause:**
In `categories.service.ts` lines 19-23, when creating a category with `parentId`:
```typescript
const category = this.categoryRepository.create({
  ...createCategoryDto,
  user: { id: userId } as any,
});
return this.categoryRepository.save(category);
```
The entity expects `parent` to be a `Category` object, but `createCategoryDto` contains `parentId` (a number). TypeORM doesn't automatically resolve `parentId` to a `parent` entity.

The entity definition:
```typescript
@ManyToOne(() => Category, { onDelete: 'SET NULL' })
@JoinColumn({ name: 'parent_id' })
parent: Category;
```

**Fix (Backend):**
In `categories.service.ts`, the `create` method needs to resolve `parentId` to an actual `Category` entity before saving:
```typescript
async create(userId: string, createCategoryDto: CreateCategoryDto): Promise<Category> {
  const { parentId, ...dto } = createCategoryDto;
  const category = this.categoryRepository.create({
    ...dto,
    user: { id: userId } as any,
    parent: parentId ? { id: parentId } as Category : null,
  });
  return this.categoryRepository.save(category);
}
```
